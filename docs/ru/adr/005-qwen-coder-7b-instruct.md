# ADR: Выбор Qwen2.5-Coder-7B (GGUF) для LLM-анализа кода

## Status
Accepted

## Context

Архитектура SecureRepo Auditor (Semantic Code Search Pipeline) использует LLM на шаге `analyze`. Модель получает исходный код и релевантные правила безопасности (найденные через Qdrant + `bge-m3`), после чего должна вернуть результат аудита в строгом формате JSON. 

Требования к модели:
- Понимание кода (Python, Java, Go, JS и др.) и сопоставление его с правилами CWE/OWASP
- Локальный инференс (конфиденциальность корпоративного кода, отсутствие доступа к внешним API)
- Низкие требования к железу (возможность запуска на виртуальной машине с 8-16 ГБ VRAM/RAM)
- Russian language support (промпты и объяснения на русском)
- Open Source
- Строгое следование инструкциям (возврат только валидного JSON без markdown)

*Qwen2.5-Coder-7B-Instruct (GGUF)*
- Тип: Code LLM (open weights)
- License: Apache 2.0 (open source)
- Parameters: 7B
- Format: GGUF (квантование Q4_K_M / Q5_K_M)
- Context: 128K токенов
- Languages: 92+ языков программирования
- Training: Обучена на огромном корпусе кода (GitHub, Stack Exchange)
- Deployment: Локально через Ollama / llama.cpp (OpenAI-совместимый API)
- Поддержка русского: Отличная

*Llama-3.1-8B-Instruct (Meta)*
- Тип: General LLM (open weights)
- License: Llama 3.1 Community License
- Parameters: 8B
- Context: 128K
- Code: Хорошее понимание кода, но модель общего назначения
- Russian: Ограниченная поддержка (хуже пишет объяснения на русском)

*DeepSeek-Coder-V2-Lite (16B MoE)*
- Тип: Code LLM (open weights)
- License: DeepSeek License (open source)
- Parameters: 16B (MoE)
- Context: 128K
- Code: Отличное понимание кода, сложная логика
- Deployment: Требует больше ресурсов (от 10 ГБ RAM), хуже совместима с простым локальным запуском

## Decision

Выбран **Qwen2.5-Coder-7B-Instruct в формате GGUF**.

Обоснование:
1. **Специализация на коде**: обучена на 92+ языках программирования, лучше фокусируется на поиске уязвимостей, чем general-purpose модели.
2. **Архитектура RAG компенсирует размер**: Модель не ищет уязвимости по памяти, а работает как классификатор: сопоставляет код с уже найденными правилами в Qdrant. Для этой задачи 7B параметров более чем достаточно.
3. **Формат GGUF и Ollama**: Запуск через Ollama поднимает OpenAI-совместимый API "из коробки" за 1 команду, что идеально интегрируется с LangGraph/LangChain без сложных зависимостей (как в случае с GPTQ).
4. **Низкий порог входа по железу**: Требует всего ~5-6 ГБ VRAM. Влезает в стандартные виртуалки.
5. **Отличная поддержка русского**: В отличие от многих аналогов, Qwen 2.5 свободно и связно пишет объяснения уязвимости на русском языке.

## Consequences

**Pros:**
- Open Source: Apache 2.0, можно развернуть на своих серверах
- Локальность: Код не покидает периметр организации
- Cost-effective: не требует затрат на API и облака
- Строгий JSON: хорошо следует формату при правильном промптинге (Few-Shot)
- Быстрый инференс: 7B генерирует токены очень быстро, что важно для Kafka-пайплайна

**Cons:**
- Менее развит reasoning по сравнению с GPT-4/Claude (может пропустить сложные логические уязвимости, например Race Conditions)
- Мелкие ошибки JSON: иногда может ошибиться с экранированием кавычек внутри кода
- Требует строгого промптинга: необходимо явно запрещать markdown-блоки

**Mitigations:**
- Fallback: использование библиотеки `json-repair` для автоматического исправления битого JSON перед парсингом
- Grounding Check: валидация наличия строки кода в оригинальном коде (fuzzy matching) для отсечения галлюцинаций
- Few-Shot Prompting: добавление примеров валидного ответа в SystemMessage

## Почему не Llama-3.1-8B / DeepSeek

| Фактор | Qwen2.5-Coder-7B | Llama-3.1-8B | DeepSeek-V2-Lite |
|--------|------------------|--------------|------------------|
| Специализация на коде | + (Code LLM) | - (General LLM)| + (Code LLM) |
| Поддержка русского | Высокая | Средняя | Средняя |
| Потребление RAM (VRAM)| ~6 ГБ (GGUF) | ~6 ГБ | ~10 ГБ (MoE) |
| Локальный запуск (Ollama)| Идеальный | Хороший | Сложнее из-за MoE |
| Качество JSON | Стабильное | Стабильное | Возможны обрывы |

## Альтернативы (рассмотрены)

| Модель | Причина отклонения |
|--------|-------------------|
| Qwen2.5-Coder-3B | Слишком мала, часто обрывает JSON, пропускает сложные уязвимости |
| Llama-3.1-8B | Модель общего назначения, хуже понимает специфичные паттерны кода и слабее пишет на русском |
| DeepSeek-V2-Lite (16B) | Тяжелее для локального инференса, архитектура MoE дает меньше преимуществ, если контекст уже сужен через RAG |
| Формат GPTQ-Int8 | Устаревший формат, проблемы с зависимостями (`auto-gptq`), отсутствие OpenAI-совместимого сервера "из коробки" |
