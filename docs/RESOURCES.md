**Для разработки/тестирования:**
- **CPU:** минимум 6 ядер
- **Память (RAM):** минимум 8 ГБ
- **Хранилище (Диск):** минимум 50 ГБ

**Для Production (боевой среды):**
- **CPU:** рекомендуется 16+ ядер
- **Память (RAM):** рекомендуется 24+ ГБ
- **Хранилище (Диск):** 100+ ГБ с настроенной стратегией резервного копирования

### 1. Расчет необходимых ресурсов LLM

Для расчета возьмем архитектуру Qwen2.5-7B (28 слоев, GQA).

1. **Веса модели (Q4_K_M):**
   Сам файл модели занимает около 4.4–4.7 ГБ. В оперативной памяти (VRAM) он займет примерно **~5 ГБ**.

2. **KV Cache (Кэш контекста):**
   Это память для хранения контекста запросов.
   * На 1 токен KV cache для этой модели в формате `fp16` требует ~56 КБ.
   * 1 запрос (1000 промпт + 1000 генерация = 2000 токенов) = ~112 МБ.
   * 5 запросов одновременно = 5 * 112 МБ = **~560 МБ**.
   * *Плюс vLLM резервирует память под PagedAttention блоки (обычно +20-30% запаса).*
   * Итого под KV Cache нужно заложить **~1–1.5 ГБ**.

3. **Активации и накладные расходы vLLM:**
   Около **1–2 ГБ** VRAM.

**Итоговое потребление VRAM:**
* **Всего:** 5 ГБ (веса) + 1.5 ГБ (KV) + 2 ГБ (overhead) = **~8.5 ГБ VRAM**.
* **Рекомендуемый GPU:** Подойдет видеокарта на **8 ГБ VRAM** (например, RTX 4060, RTX 3070, A10g) или **12 ГБ** (RTX 3060 12GB / RTX 4070) с запасом. 
* Если GPU нет, vLLM может работать на CPU, но генерация 1000 токенов будет занимать минуты. Для CPU лучше использовать `llama.cpp` (Ollama).

### 2. Оптимизация KV Cache и Paged Attention в vLLM

Одно из главных преимуществ vLLM — он делает PagedAttention и управление памятью **автоматически**. Вам не нужно писать код для этого, достаточно правильно передать флаги запуска.

Вот как настроить vLLM для вашей задачи (RAG, анализ кода):

#### 1. `--enable-prefix-caching` (Критически важно для RAG)
В вашей архитектуре LLM получает длинный `SystemMessage` (одинаковые инструкции + найденные правила OWASP/CWE) для разных кусков кода.
* **Как работает:** vLLM кэширует KV-векторы для префикса (начала промпта). При следующем запросе с тем же `SystemMessage` vLLM не будет пересчитывать токены для этого куска.
* **Профит:** Ускорение обработки промпта (Time to First Token) в 2-3 раза, экономия VRAM.

#### 2. `--max-model-len 4096` (Ограничение контекста)
По умолчанию у Qwen контекст 128K токенов. Если vLLM попытается выделить KV Cache под 128K токенов, он упадет с Out Of Memory (OOM) на 8 ГБ карте.
* **Как работает:** Вы говорите vLLM: "Максимальный запрос будет 4096 токенов" (1000 кода + 1000 правил + 1000 ответа с запасом хватает).
* **Профит:** vLLM выделяет ровно столько VRAM под PagedAttention блоки, сколько нужно. Остальное уходит на саму модель.

#### 3. `--gpu-memory-utilization 0.9`
* **Как работает:** Указывает vLLM забрать 90% VRAM видеокарты.
* **Профит:** vLLM сам создаст максимально возможный пул PagedAttention блоков. Если у вас 8 ГБ VRAM, он заберет ~7.2 ГБ, из которых ~5 уйдет на веса, а ~2.2 ГБ превратится в пул KV Cache. Этого хватит на 5 параллельных запросов с легкостью.

#### 4. `--kv-cache-dtype fp8` (Если не хватает памяти)
Если вы хотите держать в памяти не 5, а 20 одновременных запросов, но уперлись в VRAM:
* **Как работает:** Сжимает KV Cache с `fp16` до `8-bit float`.
* **Профит:** Урезает потребление памяти под контекст ровно в 2 раза. Качество генерации кода и логики практически не падает. (Поддерживается на картах Ada Lovelace 40-й серии и Hopper).
