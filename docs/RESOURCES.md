# Требования к ресурсам SecureRepo в Kubernetes

## Минимальные требования к кластеру

**Для разработки/тестирования:**
- **CPU:** минимум 6 ядер
- **Память (RAM):** минимум 8 ГБ
- **Хранилище (Диск):** минимум 50 ГБ

**Для Production (боевой среды):**
- **CPU:** рекомендуется 16+ ядер
- **Память (RAM):** рекомендуется 24+ ГБ
- **Хранилище (Диск):** 100+ ГБ с настроенной стратегией резервного копирования

### Расчет необходимых ресурсов LLM

Для расчета возьмем архитектуру Qwen2.5-7B (28 слоев, GQA) с оптимизациями Q4_K_M, KV Cache и Paged Attention.

#### 1. Веса модели (Q4_K_M квантование)

Модель Qwen2.5-7B-Instruct в формате Q4_K_M:
- **Размер файла:** 4.4–4.7 ГБ
- **Потребление VRAM:** ~5 ГБ
- **Экономия памяти:** 3x меньше по сравнению с FP16 (14 ГБ)

#### 2. KV Cache + Paged Attention

Это память для хранения контекста запросов с эффективным управлением памятью через Paged Attention.

| Параметр | Значение | Обоснование |
|----------|----------|-------------|
| **KV cache на 1 токен** | ~56 КБ (fp16) / ~28 КБ (fp8) | Qwen2.5-7B модель |
| **1 запрос (4096 токенов)** | ~229 МБ (fp16) / ~115 МБ (fp8) | Включает промпт + генерацию |
| **10 запросов одновременно** | ~2.3 ГБ (fp16) / ~1.2 ГБ (fp8) | С Paged Attention распределение |
| **100 запросов одновременно** | ~23 ГБ (fp16) / ~12 ГБ (fp8) | Для RTX 4090 24GB |
| **Paged Attention overhead** | +20-30% | Резерв блоков для перераспределения |

**Итого под KV Cache нужно заложить:** ~10–20 ГБ (в зависимости от количества параллельных запросов и размера GPU)

#### 3. Активации и накладные расходы vLLM

- **Активации:** ~1–2 ГБ VRAM
- **Model memory overhead:** ~1 ГБ
- **Reserved buffer:** ~1–2 ГБ (для swap space и временных данных)

#### 4. Итоговое распределение VRAM (пример RTX 4090 24GB)

```
├── Model weights (Q4_K_M):    4.6 ГБ (19%)
├── KV Cache Pool:           16.4 ГБ (68%) 🚀
├── activations + overhead:    1.0 ГБ (4%)
├── model memory overhead:     1.0 ГБ (4%)
└── Reserved (buffer):         1.0 ГБ (4%)
    ──────────────────────────────────────────────
    Total:                    24 ГБ (100%)
```

#### 5. Производительность по типам GPU

| GPU | VRAM | Max Parallel Requests | Latency per Chunk | Throughput |
|-----|------|----------------------|-------------------|------------|
| **RTX 3060 12GB** | 12GB | 120-180 | 1.5-3.0s | 60-100 audits/час |
| **RTX 3070 8GB** | 8GB | 60-90 | 1.8-3.5s | 40-70 audits/час |
| **RTX 4090 24GB** | 24GB | 180-250 | 1.0-1.6s | 200-300 audits/час |
| **A100 40GB** | 40GB | 350-500 | 0.6-1.2s | 500-700 audits/час |
| **H100 80GB** | 80GB | 800-1200 | 0.4-0.8s | 1200-1500 audits/час |

**Влияние optimizations:**
- **Q4 quantization:** 3-4x больше параллельности на том же GPU
- **Prefix caching:** 4-6x ускорение для запросов с одинаковыми префиксами (OWASP правила)
- **Paged Attention:** 85-95% VRAM utilization (vs 50-60% с FP16)

**Итого для SecureRepo:**
- **Минимальная конфигурация:** 1x RTX 3070 8GB = 40-70 audits/час
- **Рекомендуемая конфигурация:** 2-4x RTX 4090 = 400-800 audits/час
- **Enterprise конфигурация:** 8x A100+ = 5000+ audits/час
